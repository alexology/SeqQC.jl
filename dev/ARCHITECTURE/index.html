SeqQC.jl architecture

Status: 0.1.0. This document describes what exists and the design it is meant to grow into; planned parts are marked planned.

1. Goals and constraints

  • Single streaming pass, bounded memory, exact statistics unless a metric explicitly declares sampling or binning.
  • Metrics are independent, mergeable accumulators; the engine knows nothing about individual metrics.
  • Parsing, analysis and reporting are separate layers. Results are plain Julia data (QCResult with NamedTuple metric results); reports (JSON, HTML, MultiQC, FastQC-like) are planned consumers of QCResult only.
  • Deterministic results: integer accumulators everywhere possible; floating-point sums are accumulated in a fixed order.

2. Prior art (survey)

Summary of the documented behaviour of established tools, from the maintainers' documentation as known to the author; not re-verified online in this session (no network research was performed in Phase 1). Each point must be checked against the current upstream documentation/source before it is used for a compatibility claim (tracked in ROADMAP.md).

FastQCJava, GPL-3Modules per-base quality, per-sequence quality, per-base content, per-sequence GC (with a theoretical normal fit), N content, length distribution, duplication (tracks the first 100,000 distinct sequences; long reads truncated for this module), overrepresented sequences, adapter content, k-mer content (off by default in recent versions). Positions beyond 9 grouped in bins for long reads unless --nogroup. Pass/warn/fail thresholds in limits.txt.
FalcoC++, GPL-3Re-implementation of FastQC aimed at FastQC-compatible output with higher speed.

NanoPlot / NanoStatPython, GPL-3Long-read summaries: N50, mean/median length and quality; mean read quality computed through error probabilities, not as an arithmetic mean of Phred scores; plots of length vs quality and yield over time from sequencing summaries. NanoPlot 1.47.1 is installed in WSL (~/miniforge3/envs/nanoplot).
LongQCPythonLong-read QC including coverage-free estimates from read overlaps (minimap2-based). Licence to verify.
PacBio toolsvariousHiFi/CCS BAM carry per-read tags such as np (number of passes) and rq (predicted accuracy); subread BAM carry ZMW/hole numbers. Exact tag sets differ between chemistries and software versions, so none may be assumed.

Consequences for SeqQC:

  • read quality is reported under both conventions, with explicit names (mean_read_quality = error-probability mean, mean_read_quality_phred = Phred-space mean);
  • FastQC-like modules will live in an Illumina profile with a documented compatibility mode; no compatibility is claimed before validation against reference FastQC outputs;
  • no code is copied from these tools; algorithms are re-implemented from their documented definitions. SeqQC.jl is licensed under GPL-3.0-or-later (the licence of FastQC, chosen by the owner on 2026-11-13); the FastQC compatibility layer was nevertheless built from black-box experiments only (docs/src/FASTQC.md).

IO

open_reads(f, path; threaded) sniffs gzip from the magic bytes (1f 8b), never from the extension, and the format from the first decompressed byte: @ FASTQ, > FASTA (rejected for now), B inside gzip (BAM, rejected for now). Parser and decompression errors are wrapped in SeqQCInputError with the 1-based record number. Truncation exactly at a record boundary of an uncompressed file cannot be detected by any parser; truncated gzip streams are detected by the decompressor.

Engine

for each record (FASTX, reused Record):
    seq, qual = zero-copy byte views
    summarize!(summary, seq, qual)     # one pass over seq, one over qual; validates quality bytes
    for each metric state (Tuple, unrolled at compile time):
        update!(state, ReadView(seq, qual, offset, summary, record))
  • The tuple of states makes the per-read dispatch static: _stream! is a function barrier specialised on the tuple of state types.
  • ReadSummary is computed once per read and shared: base-class counts (packed 8-bit lanes in a UInt64, flushed every 255 bases), integer Phred sum, error-probability sum (table lookup), min/max Phred, per-read error-probability mean Q. Quality bytes outside offset..'~' raise an error; there is no silent guessing of the encoding.
  • Memory: bounded by the metric states plus one record buffer; no per-position arrays. ReadLength grows with the number of distinct lengths (exact).

Metric protocol

init_state, update!, Base.merge!, finalize_metric, metric_name, plus traits requirements (:sequence, :quality, :identifier; checked against what the input format provides before any read is processed), memory_complexity, definition (stored in result.settings.definitions). Custom metrics are plain Julia types implementing these methods (tested).

Parallel reduction contract: merge! of the states of two disjoint read sets equals a single pass over their union. Integer accumulators merge exactly; floating-point read-level sums (sum_read_q) may differ by rounding, and the merge order will be fixed (by chunk index) when threads are added so that results remain deterministic for a given thread count and chunking.

Results

QCResult holds input description, platform, settings (offset, sampling, metric names and definitions), totals, metric results, warnings, software versions and elapsed time. Metric values are reachable directly (result.n50) when the name is unique across metrics, otherwise an ArgumentError names the candidates.

5. Performance design (driven by measurement)

Measurements in bench/results/ (baseline 2026-11-10, Phase 2 2026-11-12).

Done in Phase 2:

  1. Faster error sums. The serial Float64 sum of error probabilities was the slowest loop (0.8 GB/s). Phase 2 replaced it with a fixed-point sum (multiples of 2^-44, 2 GB/s); a review on 2026-11-13 showed that its quantisation moved high per-read Q values below the integer (Q67 → 66.999999), so it was replaced by four Float64 accumulators in a fixed order (≈ 1.9 GB/s in the Phase 2 micro-benchmark; whole run 0.61 → 0.64 s on 150 Mb): deterministic, error ~ n × 1e-16.

  2. Quality pass only when needed: summarize! skips quality when no metric declares :quality (ReadLength-only on plain input: 0.54 → 0.32 s per 150 Mb, within 0.1 s of FASTX parsing).

  3. Decompression task (src/io/pipe.jl, threads >= 2): a producer task inflates into 1 MiB blocks passed through a bounded Channel (depth 8) with recycled buffers; producer errors are re-thrown to the reader, early close stops the producer. −31% on gzip Illumina-like input; ~1% on the real ONT file, whose run is bound by single-stream inflate (12.5 s of 14 s).

  4. Precompilation workload (src/precompile.jl, PrecompileTools): plain and gzip analyses and the decompression task are compiled at package precompilation; a fresh process analysing 50,000 reads went from 3.24 to 0.66 s.

Measured but not changed: the Phred histogram in QualityDistribution (1.5–2 GB/s; 4-way interleaved histograms gave no gain); FASTX parsing (~44% of a plain-input run, plus ~16 B allocated per read inside FASTX).

Next candidates, in order:

  1. Member-parallel inflate for multi-member gzip (the real ONT file has members of ~31 MB; BGZF is a special case with 64 KiB members): find member boundaries, inflate members concurrently (libdeflate reports consumed input bytes), deliver them in file order. Boundaries must be validated by the chain of member ends, never assumed from a byte pattern.
  2. Chunked multi-threading of the analysis (parse in one task, analyse record chunks in workers with thread-local states, merge in chunk order).
  3. A faster parser only if FASTX becomes the bottleneck after (1)–(2), with a byte-for-byte comparison against FASTX on real data.

6. Platform profiles (planned)

A profile is a list of metrics plus defaults and interpretation thresholds; it never changes the definition of a shared metric. Illumina: FastQC-like positional modules with bounded position bins. Nanopore: run metadata parsed from read headers (runid, ch, start_time, read) only when present, sequencing-summary files as a separate input. PacBio: HiFi and CLR/subreads as distinct modes; BAM tags read only when present, with explicit missing-data counters.
