Metric definitions

All metrics are computed in one pass. Unless stated, values are exact (integer counts or ratios of integer counts). nothing marks a value that is undefined for the data (e.g. a mean over zero reads); it is never replaced by 0.

Conventions

  • Lengths are in bases (bytes of the sequence line).
  • Bases are counted case-insensitively; U is counted as T. Classes: A, C, G, T, N, ambiguous (IUPAC RYSWKMBDHV), invalid (anything else, e.g. - or .; invalid bytes produce a warning).
  • Quality bytes are decoded with an explicit offset (33 by default, 64 on request). A byte below the offset or above ~ is an error. Phred scores range over 0–93 (offset 33). Quality strings are read and validated only when at least one requested metric needs quality (settings.quality_validated).
  • Error probabilities 10^(-Q/10) are correctly rounded Float64 values. Per-read sums use four accumulators combined in a fixed order: deterministic (same result on every run and machine), relative error of the order of n × 1e-16. Per-read Q values are rounded to 6 decimals, so a read whose bases all have score Q gives exactly Q for every Q (tested for 0–93). Base-level error rates are computed from the exact Phred histogram with the same table. (Until 2026-11-13 the table was in fixed point, multiples of 2^-44; that quantisation turned a read of Q67 bases into 66.999999.)

QualityDistribution (:quality)

Two averaging conventions are reported under different names:

  • Phred-space mean: arithmetic mean of Phred scores (FastQC per-sequence quality);
  • error-probability mean: -10 log10(mean(10^(-Q/10))), the Phred value of the mean error probability (convention of NanoPlot/NanoStat and ONT basecallers). It is always <= the Phred-space mean. ONT basecallers may skip the first bases of a read when computing the read Q score; SeqQC uses all bases.
ValueDefinition
mean_base_qualityPhred-space mean over all bases (exact)
base_error_rate, base_quality_from_error_ratemean error probability over all bases and its Phred value (from the exact Phred histogram)
fraction_q20, fraction_q30bases with Phred >= 20, >= 30
base_quality_histogramcounts of Phred 0–93
mean_read_qualitymean over reads of the per-read error-probability mean Q (each per-read value rounded to 6 decimals, so that e.g. a read of Q10 bases gives exactly 10.0 and floating-point noise does not move reads across thresholds or bins)
mean_read_quality_phredmean over reads of the per-read Phred-space mean
read_quality_of_mean_error-10 log10(mean over reads of the per-read mean error probability): the convention of NanoPlot's mean_qual (nanomath ave_qual_floats, checked in the NanoPlot 1.47.1 sources on 2026-11-10). Always <= mean_read_quality
read_quality_histogram(_phred)per-read values in bins of width 0.1: bin k (1-based index k+1) holds [k/10, (k+1)/10). Binned, therefore approximate for quantiles; no median is derived from it
reads_at_least(_phred)reads with per-read mean Q >= each threshold (default 7, 10, 12, 15, 20, 30). The Phred-space comparison is exact in integers; the error-probability comparison uses the floating-point per-read value
reads_without_baseszero-length reads, excluded from read-level quality

Floating-point note: read-level means (mean_read_quality, mean_read_quality_phred, read_quality_of_mean_error) are sums of per-read Float64 values in input order. Merging states of disjoint read sets gives the same value up to rounding (tested with ≈).

Also read_quality_floor_histogram: reads by the integer part of the per-read Phred-space mean, computed exactly as div(qsum, length).

PerPositionStats (:per_position)

Exact per-position statistics for positions 1:max_positions (default 100,000):

ValueDefinition
bases[i]bases at position i
mean_quality[i]mean Phred score at position i
quality_quantiles[j, i]quantile p_j (0.10, 0.25, 0.50, 0.75, 0.90) at position i: the value of rank max(1, floor(p n)) among the n sorted scores (the rank rule FastQC uses)
base_counts[:, i]counts of A, C, G, T, U, N and other bytes (case-insensitive; U kept separate)
raw_quality_histogramsper-position histograms of raw quality bytes (!…~), so that a different Phred offset can be applied afterwards
beyond, truncatedbases at positions > max_positions, pooled; truncated = true and a warning when reads are longer

Memory: ≈ 0.8 kB per position up to the longest read (allocated as reads get longer, by doubling, capped at max_positions); independent of the number of reads. Per-position statistics are meaningful for reads of similar length; for long reads late positions are covered by few reads. FastQC-compatible tables built from these values: docs/src/FASTQC.md.

QualityVsLength (:quality_vs_length)

Matrix of read counts, rows = logarithmic length bins (20 per decade, integer lower edges ceil(10^(k/20)), last bin >= 10^9, first bin = length 0), columns = per-read error-probability mean Q in [j-1, j), j = 1…94.

Why some short-read metrics do not transfer to long reads (planned modules)

Per-position modules (per-base quality/content) assume reads of similar length aligned at their start; for reads of 1–100 kb they mix very few reads at late positions and need bounded position bins. Duplication and overrepresented sequences based on exact identity of whole reads are meaningless for error-prone long reads, where two reads of the same molecule almost never match exactly. GC distributions of long reads are much narrower (averaging over thousands of bases) and must not be judged with short-read thresholds. These points shape the Phase 3–4 profiles.
