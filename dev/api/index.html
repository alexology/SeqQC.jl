API

SeqQC.SeqQC — Module
SeqQC

Streaming quality control for sequencing reads (Illumina, Oxford Nanopore, PacBio). The analysis engine makes a single pass over the input, feeds every read to a set of independent, mergeable metric accumulators and returns a structured QCResult.

Current scope (0.1.0): FASTQ and gzip-compressed FASTQ input, generic (platform-independent) metrics. See docs/src/ROADMAP.md for planned features.

using SeqQC
result = analyze("sample.fastq.gz")
result.total_reads, result.total_bases, result.gc_content, result.n50
source

Analysis

SeqQC.analyze — Function
analyze(path; metrics = default_metrics(), platform = :generic,
        phred_offset = 33, max_reads = nothing,
        threads = Threads.nthreads()) -> QCResult
analyze(paths::AbstractVector; kwargs...) -> Vector{QCResult}

Run all metrics over the reads of a FASTQ file (plain or gzip-compressed, detected from the content) in a single streaming pass.

  • metrics: any collection of AbstractQCMetrics with unique names, including user-defined ones;
  • platform: analysis profile; only :generic is implemented in this version;
  • phred_offset: 33 (Sanger/Illumina 1.8+, ONT, PacBio) or 64 (old Illumina); quality bytes outside offset–'~' raise an error, no guessing is done (quality strings are read and validated only when a metric requires :quality);
  • max_reads: process only the first max_reads records (head sampling, not random); recorded in settings and reported as a warning when reads were left;
  • threads: with threads >= 2 (and Julia started with several threads), gzip input is decompressed in a separate task concurrently with the analysis. The analysis itself is single-threaded in this version. Results do not depend on threads.

Errors in the input raise SeqQCInputError with the record number.

source

SeqQC.QCResult — Type
QCResult

Result of analyze. Fields:

  • input::InputInfo: path, size, compression, format;
  • platform::Symbol: analysis profile (:generic);
  • settings::NamedTuple: Phred offset, sampling, metric names and definitions;
  • total_reads, total_bases: reads and bases processed by the engine;
  • metrics::NamedTuple: one finalized result per metric, keyed by metric_name;
  • warnings::Vector{String};
  • software::NamedTuple: SeqQC and Julia versions;
  • elapsed_seconds::Float64: wall-clock time of the pass (not part of the scientific result).

Fields of the metric results can be read directly when the name is unique across metrics, e.g. result.gc_content or result.n50 (equivalent to result.metrics.base_composition.gc_content and result.metrics.read_length.n50).

Metrics

SeqQC.ReadLength — Type
ReadLength()

Exact read-length statistics: number of reads, total bases, minimum, maximum, mean, median, read N50/N90 and the full length histogram.

The state keeps one counter per distinct read length (dense array for lengths below 65536, dictionary above), so memory grows with the number of distinct lengths, not with the number of reads, and every statistic is exact.

Read N50 is computed on reads, not on an assembly: the largest length L such that reads of length >= L contain at least 50% of all bases (N90: 90%). The median of an even number of reads is the mean of the two middle lengths.

source
SeqQC.BaseComposition — Type
BaseComposition()

Base counts and GC statistics.

  • gc_content = (G + C) / (A + C + G + T): N, other IUPAC codes and invalid bytes are excluded from numerator and denominator (U counts as T);
  • n_content = N / total bases, ambiguous_content = non-N IUPAC codes / total bases;
  • gc_histogram[k + 1]: reads whose own GC percentage, rounded half up to an integer, is k (0–100); reads without any A/C/G/T are counted in reads_without_acgt instead.

Invalid bytes (anything that is not a nucleotide or IUPAC code) are counted in base_counts.invalid and produce a warning in the result.

source
SeqQC.QualityDistribution — Type
QualityDistribution(; thresholds = (7, 10, 12, 15, 20, 30))

Quality statistics with two explicitly named averaging conventions:

  • Phred-space mean (FastQC convention): arithmetic mean of Phred scores;
  • error-probability mean (NanoPlot/ONT convention): -10 log10(mean(10^(-Q/10))), i.e. the Phred value of the mean error probability.

Base level (exact, from the histogram of Phred scores 0–93): mean_base_quality (Phred space), base_error_rate and base_quality_from_error_rate, fraction_q20, fraction_q30.

Read level (zero-length reads are excluded and counted in reads_without_bases): mean_read_quality (mean over reads of the per-read error-probability mean Q), mean_read_quality_phred (mean over reads of the per-read Phred-space mean), read_quality_of_mean_error (Phred value of the mean over reads of the per-read mean error probability; this is NanoPlot's mean_qual), histograms of both per-read values in bins of width 0.1 Q (bin k holds values in [k/10, (k+1)/10)), an exact histogram of floor of the per-read Phred-space mean (read_quality_floor_histogram, integer arithmetic; FastQC's per-sequence quality scores), and the number of reads whose per-read mean Q is >= t for each threshold t.

All bases of a read are used (no trimming of the read start).

source
SeqQC.QualityVsLength — Type
QualityVsLength()

Two-dimensional histogram of read length against per-read quality (error-probability mean, see QualityDistribution).

Length bins are logarithmic, 20 per decade, with integer lower edges length_edges (bin i holds lengths in [length_edges[i], length_edges[i+1]); the first bin holds zero-length reads, the last one all lengths >= 10^9). Quality bins have width 1 Q: column j holds per-read Q in [j-1, j). Zero-length reads have no quality and are not counted.

source
SeqQC.PerPositionStats — Type
PerPositionStats(; max_positions = 100_000)

Exact statistics for every read position 1:max_positions:

  • per position: number of bases, mean Phred score, quantiles of the Phred scores (10%, 25%, 50%, 75%, 90%; quantile p of n values is the value of rank max(1, floor(p n)) in ascending order), and counts of A, C, G, T, U, N and other bytes (case-insensitive; U is not merged with T here);
  • bases at positions beyond max_positions are pooled into one aggregate (beyond), and the result reports truncated = true with a warning.

Memory: about 0.8 kB per position up to the longest read observed (capped at max_positions; storage grows by doubling, so up to twice that while reads get longer), independent of the number of reads: ~0.25 MB for 300 bp reads, ~22–44 MB for 27 kb reads, at most ~80–160 MB with the default cap. The per-position quality histograms are stored on raw quality bytes, so FastQC-compatible tables (see SeqQC.FastQC) can apply FastQC's encoding guess.

Writing a metric

SeqQC.AbstractQCMetric — Type
AbstractQCMetric

Supertype of all QC metrics. A metric M implements:

  • init_state(m::M): a fresh, empty accumulator;
  • update!(state, read::ReadView): add one read;
  • Base.merge!(dst, src): add the reads of src to dst (same metric and configuration); merging must give the same result as streaming the reads of both states through one accumulator (floating-point sums may differ by rounding, see docs/src/METRICS.md);
  • finalize_metric(state): an immutable result (NamedTuple or struct);
  • metric_name(m): a unique Symbol used as key in QCResult.

Optional traits, with defaults: requirements ((:sequence,)), memory_complexity (:unspecified), definition (""). Custom metrics need no change to the engine: pass them to analyze(path; metrics=[...]).

source
SeqQC.ReadView — Type
ReadView

The view of one read passed to update!. Fields:

  • seq: sequence bytes (AbstractVector{UInt8}, valid only during the call);
  • qual: raw quality bytes, still encoded with the Phred offset;
  • phred_offset: the offset used to decode qual;
  • summary: the ReadSummary of the read;
  • record: the underlying FASTX.FASTQ.Record (reused between reads; copy it to keep it).

Metrics must not keep references to seq, qual or record after update! returns.

source
SeqQC.ReadSummary — Type
ReadSummary

Per-read quantities computed once by the engine and shared by all metrics (read through read.summary in update!). The quality fields are filled only when at least one metric declares :quality in its requirements; otherwise error_sum and mean_error_q are NaN, qsum is 0 and qmin/qmax are -1. Fields:

  • length: read length in bases;
  • a, c, g, t, n: counts of A, C, G, T (U counted as T) and N, case-insensitive;
  • ambiguous: IUPAC ambiguity codes other than N (RYSWKMBDHV);
  • invalid: any other byte;
  • qsum: sum of Phred scores (integer);
  • error_sum: sum of base error probabilities 10^(-Q/10) (Float64, fixed order of operations, see docs/src/METRICS.md);
  • qmin, qmax: smallest and largest Phred score (-1 for an empty read);
  • mean_error_q: per-read error-probability mean quality -10 log10(error_sum / length), capped at 93 and rounded to 6 decimals (NaN for an empty read).

SeqQC.aggregate — Function
aggregate(inputs; names = nothing, low_reads_fraction = 0.1) -> SampleSet

Collect SeqQC results of several samples into one SampleSet. inputs may mix QCResults, SeqQC JSON files and directories (every *.json file whose schema is seqqc-result is used, in natural order; other files are skipped with a note). Samples are kept side by side, never merged.

FastQC compatibility

SeqQC.FastQC — Module
SeqQC.FastQC

FastQC-compatible views of SeqQC results. The rules below were determined by black-box experiments on FastQC 0.12.1 outputs (no FastQC source code was read or translated); they are documented with the evidence in docs/src/FASTQC.md. Only modules listed there as validated are provided.

Analyse with metrics (or any metric set that contains ReadLength, QualityDistribution and PerPositionStats), then call the module functions on the result:

r = analyze("reads.fastq.gz"; metrics = SeqQC.FastQC.metrics())
SeqQC.FastQC.per_base_quality(r)
SeqQC.FastQC.modules(r)          # all supported modules and pass/warn/fail flags
source
SeqQC.FastQC.metrics — Function
metrics() -> Vector{AbstractQCMetric}

Metrics needed by the FastQC-compatible modules. max_positions of PerPositionStats must be at least the longest read.

source
SeqQC.FastQC.modules — Function
modules(result) -> NamedTuple

All supported FastQC-compatible modules and their flags.

source
SeqQC.FastQC.flags — Function
flags(result) -> NamedTuple

Pass/warn/fail for each supported module, with FastQC's documented default thresholds (FastQC 0.12.1 help pages and limits.txt):

(The per-sequence GC flag is not reproduced: it depends on FastQC's fitted normal distribution, which its text output does not contain.)

  • per base quality: warn if any lower quartile < 10 or median < 25; fail if < 5 or < 20;
  • per sequence quality: warn if the most frequent integer mean quality (lowest one on ties) is <= 27; fail if <= 20 — FastQC's behaviour; its help page says "below";
  • per base content: warn if |A - T| or |G - C| > 10 in any group; fail if > 20 (on the floating-point percentages, so e.g. 27.5 - 17.5 = 10.000000000000004 warns);
  • per base N content: warn if any group > 5%; fail if > 20%;
  • length distribution: warn if lengths differ; fail if any read has length 0.

SeqQC.FastQC.GCModel — Type
GCModel()

Metric reproducing FastQC's per-sequence GC counts (fractional weights per GC percentage bin 0–100). Reads of 100–999 bases are truncated to a multiple of 100, longer reads to a multiple of 1,000 (2,850 → 2,000), as FastQC 0.12.1 does. Needs :sequence. Weights are accumulated read by read in input order, as FastQC does; merging two states adds the bin sums, which can differ from a single pass in the last bits.

source
SeqQC.FastQC.AdapterContent — Type
AdapterContent(; adapters = DEFAULT_ADAPTERS, max_positions = 100_000)

Metric for FastQC's adapter content: for each adapter (name => sequence of A/C/G/T, at most 32 bases), the start position of its first exact, case-insensitive occurrence in every read. The table reports positions 1 .. maxlength - 11 as FastQC does with its default 12-base adapters; for custom adapters of another length this row count was not compared with FastQC. Occurrences starting beyond `maxpositions` are pooled and make the per-position table unavailable. As in FastQC, reads are only searched once a read longer than the adapter has been seen, so merging states of separate chunks can differ from one pass for reads of exactly the adapter's length at the start of a chunk. Cost per base is constant (2-bit rolling k-mer codes and a lookup table).

source

Truncation for DADA2 and vsearch

SeqQC.truncation_profile — Function
truncation_profile(fastq; kwargs...) -> TruncationProfile
truncation_profile(fastq_r1, fastq_r2; kwargs...) -> TruncationProfile

Reads kept (single-end) or pairs kept (paired-end, both reads must pass, as in DADA2's filterAndTrim) for every truncation length and each max_ee threshold, computed exactly in one pass.

Keywords (defaults = DADA2's filterAndTrim defaults where they exist): max_ee = [0.5, 1.0, 2.0, 3.0, 5.0, Inf], trim_left = 0 (an integer, or a tuple for R1 and R2), trunc_q = 2, max_n = 0, min_len = 20, phred_offset = 33, max_positions (truncation lengths covered; default 600 for pairs, enough for 2 × 300 bp, and 100,000 for single-end; memory grows with its square for pairs), max_reads = nothing (first records only, head sampling).

PhiX removal (rm.phix) is not modelled: with PhiX in the data DADA2 keeps fewer reads than predicted.

source
SeqQC.TruncationProfile — Type
TruncationProfile

Result of truncation_profile: for single-end input, kept[L, k] = reads kept with truncLen = L and maxEE = max_ee[k]; for paired-end input, kept[L1, L2, k] = pairs whose both reads are kept with truncLen = (L1, L2). kept_untruncated[k]: kept without truncLen. Fields also record the filter settings, the number of reads or pairs, the longest read of each file, modal_length_fraction (fraction of reads at the most frequent length, per file: well below 1 for trimmed reads or variable amplicons) and positions (truncation lengths covered, up to max_positions).

source
SeqQC.kept_reads — Function
kept_reads(profile, truncLen, max_ee) -> Int

Reads (single-end; truncLen an integer, 0 = no truncation) or pairs (paired-end; truncLen = (L1, L2), (0, 0) = no truncation) that DADA2's filterAndTrim keeps with the profile's settings and maxEE = max_ee (one of profile.max_ee). A truncLen not above trim_left is ignored, as in DADA2.

source
SeqQC.suggest_truncation — Function
suggest_truncation(profile; amplicon_length = nothing, min_overlap = 20,
                   max_ee = 2.0, min_trunc_len = 0) -> TruncationSuggestion
suggest_truncation(fastq...; amplicon_length, min_overlap, max_ee, min_trunc_len,
                   profile_max_ee = [0.5, 1.0, 2.0, 3.0, 5.0, Inf], profile_kwargs...)

Propose DADA2 truncLen values from a truncation_profile (or compute the profile first from the FASTQ files: profile_max_ee, to which max_ee is added, gives its thresholds and the other keywords are passed to it).

  • Single-end: the length that maximises the retained bases (reads kept × (truncLen − trimLeft)), ties going to the longer truncation; min_trunc_len sets a lower bound (e.g. the length the analysis needs).
  • Paired-end (amplicon_length required): the pair (L1, L2) that keeps the most pairs subject to L1 + L2 ≥ amplicon_length + min_overlap, ties going to the larger L1 + L2 and then to the longer R1. amplicon_length is the length of the sequenced fragment from the first base of R1 to the first base of R2 (primers included if they are in the reads). DADA2's mergePairs needs at least 12 overlapping bases; min_overlap = 20 leaves a margin for length variation.

max_ee must be one of profile.max_ee; the best choice for every threshold is in alternatives. The read counts are exact for DADA2's filter (PhiX removal aside); the choice itself is a heuristic that knows nothing about the quality of the ASVs inferred afterwards.

source
SeqQC.TruncationSuggestion — Type
TruncationSuggestion

Result of suggest_truncation: the proposed trunc_len (one value, or [L1, L2] for pairs) and max_ee, the reads or pairs kept and their fraction, the expected overlap of the two reads (paired-end), the best choice for every max_ee of the profile (alternatives), warnings, and the profile itself. truncation_commands turns it into DADA2 (R and DADA2.jl) and vsearch commands.

source
SeqQC.truncation_commands — Function
truncation_commands(s::TruncationSuggestion) -> NamedTuple

Commands that apply the suggestion: dada2_r (R dada2 filterAndTrim), dada2_jl (DADA2.jl filterAndTrim) and vsearch (--fastq_filter, single-end only; for pairs, merge first with --fastq_mergepairs and filter the merged reads, which this profile does not describe). The DADA2 commands apply exactly the filter of the profile (plus PhiX removal); the vsearch one has not been validated against vsearch. File names are placeholders.
